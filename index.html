Bluespec SystemVerilog · RISC-V Vector · OpenGL ES Path

Scalable Vector Machines.
8-bit to 64-bit.

The BTRON BX series is a coherent family of clean, synthesizable FPGA RTL machines that systematically revive the peripheral ecosystems and computational spirit of classic 8-bit through 64-bit platforms. From BX-16 upward the series adopts a deliberately scalable vector architecture—SVM—whose element widths, vector lengths and floating-point capabilities grow in lock-step with the host integer ISA, remaining source-compatible across the entire family and mapped onto the RISC-V Vector Extension hierarchy.

Four cores—bx-8, bx-16, bx-32, bx-64—share one design culture, one peripheral-library discipline and one progressive vector programming model. All are expressed in Bluespec SystemVerilog, target contemporary FPGAs, and are offered as an independent systems-architecture study.

00 / Series

Unifying Philosophy

Clean RTL · Peripheral Libraries · Scalable Vectors · Professional Respect

Classic home-computer and console architectures solved difficult real-time media problems under severe cost, power and transistor constraints. Their peripheral sets and specialised compute units remain instructive. The BTRON BX programme does not attempt commercial competition or cycle-accurate commercial emulation. It asks whether the essential organisation of these machines—their peripheral libraries, dual-processor or vector-unit structure, DMA and local-memory philosophy—can be re-expressed in clean, modern, synthesizable RTL that any competent engineer can read, modify and run on an FPGA.

From BX-16 upward an additional requirement is imposed: the vector capability itself must be scalable. The same programming model, the same configuration mechanism, and the same element-type hierarchy appear at every width, merely with larger minimum VLEN, wider supported element widths, and richer floating-point support as one moves from 16-bit to 64-bit hosts.

Architectural Programme

One Graduated Family

A student or engineer can begin with bx-8, master the common BSV infrastructure, then acquire the scalable vector programming model on bx-16 and simply grow the same code to the richer element widths and floating-point support of bx-32 and bx-64.

01 / SVM

The SVM Vector Extension

Authoritative Definition · Length-Agnostic · Source-Compatible Across Family

SVM is the name given to the scalable vector architecture of the BX series. It is first realised concretely on the 16-bit R1600 core and is thereafter mapped onto the ratified RISC-V Vector Extension (RVV 1.0) and its embedded subsets. Software written against the BX-16 SVM model remains source-compatible; only the available element widths and the concrete VLMAX change.

Core properties common to every width: orthogonal 16-register vector file, configurable SEW drawn from {8, 16, 32, 64}, length-agnostic kernels driven by a vsetvl-style configuration instruction, saturating integer arithmetic, widening multiplies, reductions, and—from BX-32 upward—single- and double-precision floating-point.

Vector Architecture

Concrete Realisation on BX-16

Vector registers VR0–VR15, each 128 bits (primary view 4×32-bit Q16.16 lanes; alternative 8×16-bit). Primary arithmetic format Q16.16 fixed-point with 64-bit intermediate product. Key operations include VADD, VSUB, VMUL, VMADD, VDOT, VCROSS, VLD, VST, VBROADCAST, VMAT4VEC and VWAIT.

  • VMAT4VEC4×4 matrix × vector in one instruction
  • VCROSS3-element cross product
  • ConfigIsomorphic to RVV vtype / vl
  • Domain opsRetained as custom or expanded

RVV Hierarchy

Deliberate Alignment

The vector story is deliberately aligned with the ratified RISC-V Vector Extension and its embedded subsets, because those subsets already encode a clean scaling path. The BX series maps onto this hierarchy exactly.

Length-agnostic loops written against VL and SEW compile unchanged when the host becomes RV32 or RV64. Domain-specific accelerators are either retained as custom opcodes under the RVV custom-0/1 space or expanded by the compiler into short standard sequences.

02 / Machines

The Four Cores

bx-8 · bx-16 · bx-32 · bx-64 — One Design Culture

Each machine occupies a precise place in the graduated programme. BX-8 validates the common Bluespec infrastructure and peripheral-library discipline. BX-16 introduces the authoritative SVM definition and the first OpenGL ES-style transform path. BX-32 and BX-64 scale the same model onto 32-bit and 64-bit RISC-V hosts with progressively richer floating-point and vector length support.

All four share clean RTL, selectable peripheral libraries, open or cleanly designed ISAs, the scalable vector model (from BX-16), FPGA-first implementation, and a professional stance that honours the original engineers.

03 / OpenGL ES

OpenGL ES Path

Transform · Lighting · Vertex Pipeline · Length-Agnostic Kernels

The primary non-legacy workload considered across the series is software 3D rendering of the complexity that tinyGL and related fixed-function OpenGL ES 1.x subsets can express: low-to-mid polygon counts, simple lighting, perspective-correct or affine texturing, and a software Z-buffer. The architecture must make the transform-and-lighting stage and the inner rasterisation loops substantially faster than a pure scalar host, without requiring a full modern GPU.

On BX-16 the SVM unit supplies 4-wide Q16.16 matrix–vector products and cross products. On BX-32 the same length-agnostic loops gain FP32 and wider VLEN. On BX-64 they gain FP64 and the full RVV operation set. A single high-level 3D library can therefore target every machine from the 16-bit entry point upward.

Graphics Workload

From Fixed-Point to Full FP

BX-16 introduces saturating arithmetic, widening multiplies and simple reductions—exactly the operations useful for Amiga-style blitter work, audio mixing and early OpenGL ES-style transform kernels. BX-32 adds single-precision floating-point essential for Dreamcast-style matrix work and full vertex processing. BX-64 supplies the complete set required to cover Emotion Engine and N64 RSP geometry rates.

04 / Notes

Technical Notes & Academic Record

Umbrella Study · Companion Notes · Scopus-Ready Foundation

The series is documented as a set of independent systems-architecture technical notes prepared for professional consideration. The umbrella note situates the four cores within a single coherent programme. Each companion note supplies the detailed architectural intent, BSV organisation, vector mapping and relationship to the original platforms. All are framed for archival and academic use.

Sources and documentation are offered under open terms suitable for laboratory reproduction, classroom study and further research. The work does not claim commercial product status; it is an architectural study that honours the original engineering.

05 / Invitation

Living Subjects of Study

Respect · Openness · Progressive Vector Capability

The BTRON BX series is an invitation to treat classic media-processor architectures as living subjects of study. By re-expressing their peripheral ecosystems in clean Bluespec SystemVerilog, and by imposing a single scalable vector architecture (SVM) from BX-16 upward, the series offers a practical path from 8-bit MSX-class machines to 64-bit vector architectures whose software model remains coherent across the entire family.

The four cores—bx-8, bx-16, bx-32 and bx-64—form one graduated programme united by methodology, by a progressive vector capability, and by respect for the original engineering.
